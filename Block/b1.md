# BLOCK ONE - Requirements Analysis & Specification Log

## Overview
This document serves as the tracking log and formal specification breakdown for **BLOCK ONE** of the CRM system, derived from `block_1.pdf` and accompanying reference UI designs.

---

## 1. User Management & Role Hierarchy (Role Master)

### 1.1 Field Requirements for User Creation
- **User Name** (Required text)
- **Contact Number** (Required phone/mobile number)
- **Password** (Required for authentication setup)
- **Role** (Required dropdown selection: Super Admin, Admin, Manager, Team Leader, Executive, Custom Roles)
- **Email ID** (Optional/Required email address)
- **Reporting Person** (Required mapping for hierarchy: Manager/TL/Super Admin)
- **Employee ID** (Unique employee identifier string)
- **Bulk Add Users**: Modal and batch import support as shown in UI reference.

### 1.2 Role Master Breakdown & Access Rights (RBAC)
| Role | Access Scope & Capabilities |
| :--- | :--- |
| **Super Admin** | • Only role capable of creating new employee IDs & deleting user accounts.<br>• Full system administrative privileges.<br>• Can toggle Admin access ON/OFF.<br>• Password management for any user.<br>• Performs lead reassignment.<br>• Final approval for sales before sending to eKYC.<br>• Creates & manages custom multi-level roles. |
| **Admin** | • Access toggled ON/OFF directly by Super Admin.<br>• High-level operational management based on assigned custom permissions. |
| **Manager** | • Scoped visibility: Can view and monitor Team Leaders & Executives underneath them in the organizational tree.<br>• Performance tracking (Sales, MITC Status, Compliance status, etc.). |
| **Team Leader (TL)** | • Scoped visibility: Can view and monitor Executives directly assigned under them.<br>• Teammate performance tracking. |
| **Executive** | • Restricted visibility: Strict data isolation — access limited solely to their own assigned data and leads. |

### 1.3 Executive Assignment & Team Selection Rule
- When creating or editing a user with the **Executive** role, the system **must prompt** to assign a Team Leader and/or Manager.
- Super Admin can re-assign an Executive to any Team Lead or Manager.

## 2. Workflows & Performance Monitoring

### 2.1 Sale Approval Workflow
```
[ Executive / Employee makes a Sale ] 
              │
              ▼
[ Notification sent to Super Admin ]
              │
              ▼
[ Super Admin Approval Decision ]
       ├── Approve ──> Lead moves to eKYC Stage
       └── Reject  ──> Lead flagged for revision
```

### 2.2 Team Monitoring Dashboard
- Managers & Team Leaders can access a dedicated **Team Performance View**.
- Metrics tracked per teammate:
  - Total Sales & Conversions
  - MITC (Most Important Terms & Conditions) Status
  - Compliance Status
  - Active Lead pipeline breakdown

## 3. Directory Controls, UI Settings & User Lifecycle

### 3.1 Directory List & Controls
- **User Directory Table**: Displays Name, Mobile Number, Reporting To, Email, Role, Expiry/Created Date, Status badge (Active/Inactive), and Action Menu (`⋮`).
- **Default View**: Displays **Active** users only by default.
- **Search & Filters**: Real-time search by name/mobile/email + Status filter dropdown (`All`, `Active`, `Inactive`).
- **User Actions**: Edit user details, Toggle Active/Inactive status, Disable user access, Change Password (Super Admin only).

### 3.2 System Settings & Customization
- **UI/UX Color Theme Switcher**: Option in settings to dynamically change the primary accent color / UI theme of the CRM interface.
- **Custom Role Builder**: Interface to create and modify multi-level custom roles with granular permission toggles (Annexure-I specification).

---

## 4. Account Rules, Lead Reassignment & Deletion Protocol

### 4.1 Deletion & Status Rules
- General users cannot delete accounts.
- Resigned staff must be set to **Inactive** status.
- Only **Super Admin** can permanently delete user accounts.

### 4.2 Lead Reassignment Protocol
- **Reassignment of Inactive Users' Leads**: Super Admin can reassign leads owned by inactive users to active staff.
- **Pre-Deletion Reassignment Rule (Mandatory Lock)**:
  - System blocks deletion of any user account if they hold active leads.
  - Super Admin is prompted with a mandatory reassignment wizard to re-assign all leads to chosen active user(s) before deletion is executed.
- **Lead History Preservation**:
  - Full activity log and lead audit history transfers seamlessly to the newly assigned user.

## 5. Implementation Roadmap & Architecture
- **Frontend Stack**: Vite + React + Vanilla CSS (Design system with sleek theme builder & glassmorphic dark/light aesthetics).
- **State Management**: Reactive state holding users, leads, audit history, role matrix, sales approval queue, and theme settings.
- **Mock Data Engine**: Pre-loaded with realistic users (matching NeoDove screenshots), leads, sales workflow state, and team hierarchy for instant live testing.
- **Multi-Block Extensibility**: Clean separation of modules, central context store, and plug-and-play navigation allowing subsequent blocks (Block 2, Block 3, etc.) to be added effortlessly.
